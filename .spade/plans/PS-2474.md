# Plan for: Ship the `leads` skill into SPADE

**Scope:** PS-2474

**Delivery shape:** One bundle, four tasks, one pull request.

**Approval:** The human explicitly approved the Scope shape and instructed this delivery agent to Plan and Deliver in one run.

## Technical Approach Summary

Vendor the host-neutral `leads` skill as an advisory SPADE capability that captures out-of-scope discoveries without changing the five-phase loop, `/spade` autonomy picker, or critical-skill set.
Lock its routing, tracker fallback, management actions, reporting, and terminating-completion behavior in the existing skill-authoring corpus, then register it as SPADE's eighteenth skill and release the additive capability as v3.4.0 through the canonical projection and lifecycle machinery.
Keep `/spade-learn` responsible for reusable carry-forward knowledge while `leads` owns actionable out-of-scope discoveries awaiting later triage.

## Architectural Alignment

- The behavior remains host-neutral Markdown under `src/skills/leads/` and uses `{{SPADE_SHELL}}` for shell examples.
- The skill is advisory, so it is registered in `skills:` but excluded from `critical_skills:` and the `/spade` autonomy picker.
- The existing GitHub Issues default, tracked `LEADS.md` fallback, and `.spade/config` Linear override are preserved without adding a tracker resolver or runtime integration.
- Generated Claude, Codex, plugin, marketplace, and global-install trees are updated only through `scripts/project-hosts.sh`.
- The change does not edit `src/skills/spade-review/SKILL.md`, rename the skill to `spade-leads`, or alter PS-889 content.
- No conflict with `ARCHITECTURE.md`, `PATTERNS.md`, or `ANTI-PATTERNS.md` was found.

## Risks and Assumptions

- **R1 - Behavior drift while adapting the vendored skill:** Host-neutral rendering could accidentally omit a command, fallback, or reporting rule.
  Mitigation: preserve every supplied behavior and add authoring-contract anchors for the five mutation classes plus terminating completion.
- **R2 - Advisory capability accidentally becomes lifecycle-critical:** Adding `leads` to `critical_skills:` or `/spade` would change autonomy and acceptance behavior.
  Mitigation: register it only in `skills:` and assert the expected critical count remains unchanged.
- **R3 - `/spade-learn` boundary becomes ambiguous:** Users could confuse an actionable discovery with reusable project knowledge.
  Mitigation: document the complementary boundary in `docs/FRAMEWORK.md` and keep both public descriptions distinct.
- **R4 - Version and count drift across release surfaces:** v3.4.0 touches the capability manifest, catalogs, documentation, migration chain, and projections.
  Mitigation: update version authority first, regenerate all projections, run projection drift checks, and rely on exact authoring/catalog assertions.
- **R5 - Lifecycle fixture circularity:** The 3.4.0 fixture must cite an immutable commit that already contains the released fragments.
  Mitigation: commit all release content before deriving the fixture, record that exact commit in `.release-commit` and `historical.tsv`, then validate every published version through 3.4.0 twice.
- **R6 - Stacked-base contamination:** The branch contains the approved PS-889 v3.3.0 release and must not rewrite it.
  Mitigation: keep `origin/spade/ps-889-unhinged..HEAD` limited to PS-2474 commits and review the final diff against that base.
